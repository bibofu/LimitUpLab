# 2026-10-09 首页持续加载

## 现象和诊断

生产版本为 `v1.5.2` / `6c6786c`。用户访问首页持续显示“正在加载 LimitUpLab 数据”。
浏览器复现；首页 HTML、静态资源、`/health` 正常，容器健康、CPU、内存及磁盘无耗尽迹象。
首板、连板、炸板、近期涨停和首板评级五个接口正常返回；市场概览和晋级统计在 22 秒
探测预算内始终未返回。后端健康接口不访问这些外部数据源，因此不能证明页面可用。

阻塞链路：

- 市场概览同步查询三类指数；AKShare 历史请求未统一限定整个调用的最长时间。
- 晋级统计同步读取新浪交易日历；安装版本中的 `requests.get(url)` 没有 timeout。
- 两者在网络访问期间持有 `without_proxy` 的进程级 RLock；一条未结束的请求可能阻塞
  后续采集。同日期晋级请求还会在 `Future.result()` 上无限等待。
- 前端用 `Promise.all` 等待七项全部完成，且 fetch 没有截止时间，导致单个阻塞扩散为全页不可用。

进一步在同一生产容器的新 Python 进程分别探测，日历约 3.54 秒、指数约 4.95 秒成功；
常驻进程接口仍未返回。该进程可见多条 futex 等待及一条 HTTPS 连接。这些证据支持
旧请求/共享锁持续阻塞的判断，但没有捕获 Python 线程堆栈，不能确定最先卡住的具体源。
不能将此事件概括为当前所有供应商均不可用，也不能据此判断供应商的长期稳定性。

## 临时恢复

确认活动 Agent 运行数为零后，获取既有发布共享锁，确认无维护标记及日更/备份容器，
仅重启原后端容器。未更换镜像、改写配置或恢复数据库。

重启后市场概览约 4.81 秒、晋级统计约 2.22 秒返回 200，日期均为 2026-10-09；
指数返回三项、晋级统计返回五天，未报告缺失。浏览器首页恢复。重启只清除旧阻塞，
不代替下面的代码修复。

## 修复

- `2237d3d`：指数整批 10 秒、交易日历 8 秒，使用可终止 spawn 子进程；代理环境锁
  不再由父进程在上述采集期间持有。成功缓存保留在父进程，合并并发请求并限制等待。
  超时/失败不缓存，过期成功结果不冒充当前数据，日历不可用时不猜测交易日。
- `cbd4e05`、`782f7c4`：首屏按模块独立加载/报错/重试，正常列表、导航和 Agent 区域
  不等待指数或日历。首页 GET 限时 20 秒，其他 GET 120 秒，聊天 POST/SSE 不变。
  刷新中止旧请求并忽略过期返回，评级仅与相同日期事件关联。

指数预算覆盖三个标的和全部回退；某来源挂起可使整批返回缺失，不承诺超时后还执行
剩余回退。进程清理最多额外约 4 秒。当前修复不将系统改为多实例服务。

## 验证

- 当前完整离线验收：1,685 后端测试、22 子测试、47 前端测试通过；保留三条已有依赖
  弃用警告。独立测试数据库、关闭真实 LLM。
- Golden 契约校验：61 场景、84 回合通过，不代表新的模型质量成绩。
- 本地浏览器故障演练：概览延迟 30 秒、晋级返回 503，其他本地数据和导航仍显示；
  20 秒后概览显示局部超时；晋级来源恢复后单独点击重试能显示统计。
- 生成的接口样本、演练服务及验证日志保存在忽略的 `output/` 下，不提交数据或用户会话。

发布结果需单独核验标签流水线、生产 SHA、接口及真实浏览器，不能仅凭测试通过声称上线。
