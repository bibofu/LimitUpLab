## 真实工具问题：103 被截断成 100

同一日期、同一本地数据、未联网：

- 独立 SQL：103 只收盘涨停；`market_summary(include_limit_down=false)`：103。
- `limit_up_events(event_status=closed, limit=100)`：`matched_count=103`、`returned_count=100`，本身保留了截断信息。
- `market_event_pool(event_type=limit_up, result_mode=count, limit=100)`：`matched_count=100`。
  生产实现先调用上限 100 的事件列表，再对截断后的 `items` 取长度，丢失了真实命中数。

原始冲突录制与独立来源均保留，记录为 badCase BC-077（工具问题已复现，尚未修复，没有 Agent 回答失败标签）。
不把标准答案改成 100，也不为保持“全通过”删掉 Q01。Q01 仍可进行题意复核，但正式质量基线先暂停。
任何题的后续运行一旦依赖这个错误计数，也须单独归因工具/数据问题，不能由终态或 Judge 自动归为 Agent 失败。

建议下一项工程工作是修复这个已有业务工具的计数/截断语义，覆盖 count/list、超过上限与小集合的回归；
修复后重录新的 World，保留本版本及问题证据，不做 Prompt 特例，也不扩评测框架。
