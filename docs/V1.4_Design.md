# LimitUpLab V1.4 设计：回答质量与盘前策略优化

> 设计日期：2026-09-08
>
> 状态：待执行设计，不代表功能已实现或策略已验证。
>
> 基线：V1.3 系列；线上已发布 `v1.3.2`。本文件不创建 V1.4 发布标签。

## 1. 版本定位

V1 阶段暂不扩展大型功能，保留 **Agent 问答、盘前推荐、复盘、涨停池展示** 四项核心能力。V1.4 从“功能是否具备”转向“已有功能是否可靠、好用、可验证”，集中推进两条主线：

1. 完善 Agent 回答：听懂问题、查对数据、直接回答、解释清楚，遇到证据不足时如实说明。
2. 完善盘前推荐策略：先保证输入和样本可信，再验证现有筛选、评分与动态调整的价值，逐步提高解释性、稳定性和可评估性。

复盘承担结果反馈和策略验证，涨停池承担基础事实核对。两者只做支撑上述目标所需的修复与一致性优化，不单独扩展新产品模块。

本阶段优先级以本设计为准；历史路线图中的集合竞价、低位挖掘、平台化等事项，不因仍有未完成标记而自动进入 V1.4。

项目始终用于研究、解释与风险提示，不输出买卖指令、仓位、目标价或收益承诺。提高策略质量不等于承诺预测有效。

## 2. 范围与不变量

| 模块 | V1.4 重点 | 保持不变的边界 |
| --- | --- | --- |
| Agent 问答 | 意图理解、证据准确性、回答完整性、多轮承接与失败表达 | 复用现有受控工具；LLM 不计算原始评分或补造事实 |
| 盘前推荐 | 一进二评分诊断，缩量整理与高位回撤规则验证，数据质量与展示解释 | 三个入口并列；不强行统一为同一种预测模型 |
| 复盘 | 核验样本资格、Outcome 覆盖和失败原因，反馈策略研究 | 历史原件保留；历史展示与严格前向统计分开 |
| 涨停池 | 日期、股票范围、事件与评分来源一致性 | 不新增盘中交易终端或大规模看板 |

继续遵守以下约束：

- 一进二默认展示最新可用快照，明确基准日、目标日、生成时间和阶段；旧快照可展示不代表今日已有正式终选。
- 服务未在开盘前运行时，允许说明状态并读取已有快照，不以开盘后的信息补造盘前终选。
- 缩量整理、高位回撤有符合项时只展示符合项；无符合项时最多展示 6 个接近项。接近项不计入正式候选，不放宽规则凑数，维持现有稳定排序。
- 形态观察当前属于 `recomputed_observation`；历史推算的首次符合日期不代表当时实际发布，不混入一进二前向统计。
- 评分、输入 Facts、数据缺失、信息截止和版本必须可追溯；历史预测与已固化复盘不因优化被覆盖。

## 3. 主线一：完善 Agent 回答

### A1. 先建立问题与失败基线（P0）

以现有评测题库为起点，按四个核心功能整理高频问法；补入人工使用中发现的失败案例，不先大范围改提示词。生产案例需去除身份信息、密钥及非必要会话内容，再形成可公开提交的小型 fixture。

题库重点覆盖：

- 市场与涨停池：指定日期、首板/连板/炸板、数量、排序、筛选与完整名单。
- 候选解释：为什么入选、为什么没入选、评分依据、风险和缺失信息。
- 复盘核对：当时名单、后续结果、比较基线、尚未成熟或不合格样本。
- 多轮追问：这只、其中、换一天、两只比较，以及新问题不误继承旧条件。
- 边界情况：无数据、部分数据、工具失败、过期快照、超出 V1 范围及诱导交易建议。

每条案例保存问题、上下文、预期意图和日期、必要证据、答案必须覆盖的要点、禁止出现的结论。评估语义和事实，不把固定措辞作为唯一正确答案。

按“理解错误 → 工具/参数错误 → 数据不足 → 事实引用错误 → 表达不完整 → 交互或耗时问题”归类。先处理影响面大的错误日期、错股票、错名单和编造数据，再处理冗长、重复和措辞问题。

### A2. 沿回答链路逐层修复（P0）

1. **理解层**：用户显式日期、股票、数量、筛选条件优先于页面默认值和会话记忆；存在会改变查询结果的歧义时做简短澄清。
2. **查询层**：优先修正 Capability / Query Contract、工具参数与读取路径，不用叠加关键词或提示词掩盖后端错误。只有现有能力确实无法回答核心问题时，才评审最小工具补充。
3. **证据层**：统一股票身份、交易日、统计分母和快照阶段。名单、分数、排名等确定性结果直接使用结构化数据；记忆只能承接语境，不能充当新的行情证据。
4. **生成层**：默认先给问题的直接答案，再给关键依据与必要限制。单事实短答、名单用紧凑列表、解释或比较才展开；不要求每个问题都套长模板。
5. **校验与降级层**：沿用已有事实校验与安全边界。证据冲突或生成校验失败时返回已核验内容和缺口说明；禁止无限重试和把失败包装为“没有符合股票”。

每次修复必须先固化失败案例，再调整最小相关层，随后回归相邻问法与多轮场景。以证据不足为由正确拒答，与有数据却答不出来，应分别计数。

### A3. 打磨解释与使用体验（P1）

- 候选说明围绕“触发了什么条件、哪些事实支持、哪些事实不支持、哪里缺数据”，不机械复述所有指标。
- 新闻或热度相关解释区分事实、相关性和推测，不把时间上同时发生写成确定因果。
- 推荐、涨停池、Agent、复盘在引用同一日期和同一批次时保持一致；不同批次导致的差异要说明，而不是强行显示成一致。
- 工具失败保留可用的部分结果，明确失败范围和可执行的重试方式；流式中断不留下貌似完整的半段结论。
- 追问只围绕当前证据与已有能力生成，避免固定推荐词、内部字段泄漏及不必要的免责声明堆叠。
- 记录首字响应、总耗时、工具次数与实际 token 用量；先优化重复读取和无必要的生成，不以减少证据检查换取速度。

### A4. 评测与验收

复用现有 Core、Product、Query Contract、Paraphrase、Conversation 评测，不另建大型评测平台。离线回归验证确定性行为；真实模型回归验证理解与最终表达，二者分别报告。Planner 通过不等于最终回答通过。

拟采用以下版本门槛，执行 A1 时冻结具体题集、统计方式与基线，不在看到优化结果后修改分母：

- 全部既有离线回归及新增关键案例通过。
- 固定真实模型验收集每题至少 3 次；关键日期、股票、数值、名单编造、未来信息引用与交易指令属于硬失败，验收集中不得出现。
- 人工按“直接回应、要点完整、证据可核对、多轮承接、表达清晰”打分，建议总体合格率目标为至少 95%；这是待验证目标，不是当前成绩。
- 保留未用于调优的验收题，避免只对开发题库有效。新增题与旧题分别统计，汇总时同时给出题数、轮数与失败分类。
- 同一模型、配置、数据及运行条件下比较质量、P50/P95 耗时和成本；P1 性能优化不得引入关键质量退化。没有实测前不承诺绝对延迟。

## 4. 主线二：完善盘前推荐策略

### B1. 数据与样本可信是前置任务（P0）

先检查推荐链路的事件覆盖、日 K 连续性、交易日历、成交量单位与来源、价格异常、证券状态及证据时间。区分源数据缺失、缓存未补齐、规则真实排除和有效空池，不能统一表现为“没有股票”。

为每次研究明确候选总体、可评价数、排除原因、缺失数、日期范围、输入摘要和规则版本。覆盖不足时先说明研究范围；需要历史补齐时另列任务和数据来源，不在生产页面请求中临时全市场扫描。

复盘优先补齐已成熟 Outcome，严格按交易日对齐 D+1 至 D+5，未成熟、缺失和无效数据分别列示。未知结果不能按失败或成功填充。实际覆盖率、有效日期数和前向样本数在执行时重新审计，不沿用旧文档中的历史数字。

### B2. 一进二接力：验证评分的增量价值（P0 → P1）

先诊断现有规则，不预设必须新增因子或提高某个权重：

1. 固定当前候选范围和评分版本，拆分基础规则分、收盘已知情报和盘后动态修正。
2. 检查高分未晋级、低分晋级、候选过滤遗漏与关键缺失案例；先判断是数据、过滤、排序还是解释问题。
3. 对因子和动态修正做消融：同样本、同信息截止下比较启用与不启用的结果，检查重复计分、相关因子堆叠及少数日期主导。
4. 优先形成少量、可解释的修正假设，一轮只修改一个清晰问题。记录假设、预期影响和否定条件，再评估结果。
5. 候选版本进入既有 Challenger 流程，验证通过且人工批准后才替换 Champion；没有稳定证据时保留原规则。

主指标沿用同日 Top10 的 D+1 一进二晋级率及其相对基线差值，同时报告成熟样本分母、日期数与覆盖率。对照包括同日合格候选池、最早封板和固定随机基线；全市场首板作为独立背景，不能与经过过滤的候选池混为同一分母。

D+1 至 D+5 价格路径、异常下行与结果集中度作为辅助风险观察，不当作可实现收益。一字、停牌或数据异常导致的解释限制需单列，不能在看到结果后移除不利样本。

### B3. 缩量整理与高位回撤：先验证分类，再研究区分能力（P1）

两者保留独立目标，不按一进二晋级率评价所有形态，也不直接加上未经校准的概率或综合分。

| 策略 | 核心问题 | 首轮执行思路 |
| --- | --- | --- |
| 缩量整理 | 当前量比、区间、位置与持续天数是否准确描述整理；缩量是否提供额外区分信息 | 先复核量价单位和窗口；在同类价格结构、相近锚点年龄下比较缩量与非缩量，复用现有压力检查 |
| 高位回撤 | 局部高点与回撤计算是否可靠；观察池能否区分不同回落路径 | 先验证参考高点不含未来数据；固定回撤分组，观察后续路径与风险，再评估修复特征是否值得单独实验 |

阈值调整是待检验假设，不是本设计已确定的改动。不得因为候选少而降低门槛，也不把“回撤较深”解释为安全或止跌。当前版本和排序作为对照保留。

形态评价先明确观察起点、D+1 至 D+5 路径定义、同日参照组和去重规则，再读取后续结果。同一股票、涨停锚点、形态的首次符合与持续观察分开；两种形态重叠不能重复当作独立样本。正式候选、接近项、数据不足项分别统计。

继续复用只读研究脚本，记录输入与脚本摘要。历史重算只能支持探索；如后续确需前向验证，先评审最小的独立观察留档方案，冻结生成时间、输入与结果，从启用日积累。该留档不得写入一进二预测表，也不自动扩展为三策略统一平台。

### B4. 研究与上线门槛

- 开发期、验证期按时间划分；涉及五日结果时处理跨区间标签重叠，不能随机拆散同日或同锚点样本。
- 调参只使用开发期；固定规则后查看保留验证期。报告所有已尝试方案，控制反复试阈值带来的选择偏差，不只展示最优曲线。
- 历史研究、收盘基线、旧版本样本、现行盘前终选分组展示。只读历史回放不能替代严格前向验证。
- 一进二沿用现有 Champion/Challenger 晋级约束，包含至少 60 个结果完整交易日等门槛，具体以当前代码和规则为准；满足天数不是充分条件，也不因 V1.4 发布计划放宽。
- 形态观察不套用一进二的晋级门槛；在实验前固定其独立样本充分性与风险判据，未建立判据前不作有效性结论。
- 数据或实现纠错可以在回归充分后独立发布；影响名单或分数时记录版本、生效日与影响范围。研究性规则调整需先验证、人工审核，再通过版本标签上线。
- 若证据不足，交付诊断、缺口和下一步采样方案，保持现有生产规则。V1.4 工程验收可以完成，策略有效性验证仍可继续。

## 5. 执行顺序与交付物

采用小批次迭代，不一次性改完回答链路和三套规则。以下是依赖顺序，不是固定工期承诺。

| 阶段 | 重点任务 | 交付与退出条件 |
| --- | --- | --- |
| ① 基线与问题清单 | A1、B1：冻结题库、审计数据和样本，归类问题 | 有可复现案例、基线指标和按影响排序的待办；区分代码错误与研究假设 |
| ② 可靠性修复 | A2：修正理解/证据链；修复推荐数据、时间与展示不一致 | 关键失败案例回归通过；旧快照、空池、错过终选等边界保持兼容 |
| ③ 质量与策略实验 | A3、A4、B2、B3：优化回答，逐项验证策略假设 | 同条件前后对比；保留失败实验；研究结果不直接改变生产规则 |
| ④ 验收与发布 | 汇总回答评测、策略结论、风险与未完成项 | 完整工程验收、人工业务验收、发布记录；策略可结论为继续观察 |

每项任务统一使用“问题 → 证据 → 最小改动/实验 → 回归 → 结论”的记录格式。任务要能明确落到一类错误或一个假设，不使用“全面优化 Agent”“提高推荐准确率”作为不可验收的单项待办。

最终交付包括：可复现评测题与测试、Agent 质量对比摘要、策略数据健康与研究结论摘要、已批准的最小代码修改、V1.4 验收与变更记录。原始会话、数据库、备份及生成明细保留在受控本地位置，不随 Git 提交；公开摘要只使用已核验且适合公开的信息。

## 6. 工程落点与发布要求

- Agent 复用 `capability_contract.py`、`query_contract.py`、`tool_execution/`、`answer_grounding.py`、`chat_answer_validation.py` 与 `eval_runner.py`，按失败所在层修复，不重复建设规划与校验系统。
- 策略复用 `recommendation_intelligence.py`、`scoring_policy.py`、`scoring_policy_optimizer.py`、`consolidation.py` 和现有只读研究脚本；业务规则保持确定性且带版本。
- 每个已完成修改按项目约定独立提交，只纳入相关文件；发布前运行完整 `scripts/check_project.py`，另做真实模型验收和浏览器业务核验，不能只用构建成功代替产品验收。
- 关键回归覆盖：历史/最新日期、多轮追问、工具失败、三个策略入口、有符合项/接近项/数据不足、旧快照兼容、未运行服务时的展示、信息截止与历史原件保留。
- V1.4 标签仅在实际验收后创建，沿用双平台 CI 和受保护自动部署；普通开发提交不触发生产升级。涉及结构迁移时遵守现有维护与恢复流程，不能假定旧镜像可直接回滚。

## 7. 本阶段明确不做

- 不新增第四类大型业务入口，不恢复集合竞价或低位挖掘，不扩展盘中交易功能。
- 不建设统一多策略平台、自由协作式多 Agent 系统或自动调参上线系统。
- 不开展用户体系、支付、移动端、数据库迁移或多实例部署等独立建设。
- 不大规模重做界面；只调整妨碍理解、核对和使用的细节。
- 不为追求演示数字重写历史、不以补算伪装前向结果、不让 LLM 自行决定候选和权重。

影响现有四项能力的安全、数据损坏或可用性问题仍可优先修复，不受上述功能冻结限制。

## 8. V1.4 完成的判断

V1.4 的成果应是：**Agent 回答中的主要错误有案例、有修复、有质量对比；盘前策略的数据缺口、规则依据和验证结论更清楚；复盘能持续提供可信反馈。**

不以新增页面数量或短期样本表现定义成功。可以保留暂未证明有增量价值的规则，也可以否定一个新假设；每次优化都应让已有能力更可靠，而不是让结论更激进。
