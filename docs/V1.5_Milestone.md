## 本阶段完成的工作

### 任务理解、工具与证据交付

- 在已有 LangChain 原生工具调用和有界 ReAct 基础上收紧最终出口：必须使用类型化 `finish`，普通模型文本不能直接标记为完成。
- 26 个公开工具从共享契约派生严格参数 Schema 与 `StructuredTool`，在调用前检查工具权限、参数及历史时点能力。
- 结构化 Input Reviewer 区分独立问题与追问，记录待补信息、日期和展示字段；追问使用历史实体及实际工具参数消歧，事实必须重新查询。
- 服务端从本轮证据渲染 `finish.table`，核对要求的字段、顺序、集合范围和缺失项；区分完整空结果、查询不完整、源截断与预览省略。
- 明确 `complete / partial / empty / refuse` 的交付边界；混合请求拒绝交易指令后仍应完成允许的研究内容。独立合规 Critic 检查最终回答。
- 退役旧自然语言正则编译器及 Claim Ledger。开放文本尚无逐句事实正确性保证，引用证据不等于解释已经被证明。

实现入口见 [集成说明](LangChain_Integration.md) 和 [代码阅读指南](code-reading-guide.md)。

### 流式回答与运行恢复

- 从原生 `finish.answer` 增量显示正文；草稿通过 revision 与 `answer_start / answer_delta / answer_reset` 管理，失败、取消或校验不通过时撤回。
- `completed` 返回已原子持久化的最终回答并替换草稿。前端处理 Unicode 偏移、重复片段与断线恢复。
- 保留 owner/session 隔离、请求幂等、调用记录和协作式取消；SSE GET 重连只读取已有结果，不触发新模型调用。

### Golden 粗评与裁判诊断

- 新评测框架位于 `backend/evals/golden`，在隔离 SQLite 和冻结合成工具环境中运行生产 Agent，独立保存标准答案、工具轨迹、证据和可见回答。
- 主套件覆盖 31 个单轮、20 个多轮、10 个异常或安全场景，共 61 场景、84 回合；分别检查任务交付、事实、日期、集合、格式、调用和安全边界。
- 确定性检查结合两阶段独立裁判，分别检查最终交付和展示过的内容，撤回草稿仍保留审计记录。结果区分通过、失败、待复核和模拟环境错误。
- 增加调用预算、运行前指纹、可恢复报告、版本比较和程序生成的证据引用 ID；不通过隐式重试或自动改写判断隐藏异常。
- 完成裁判重复诊断、8 项真人定向标注及 v17 修复复验；保留首次标注、更正和历史原件，不追改旧成绩。

默认 `v1_close_review` profile 的 24 个工具中有 11 个模拟实现；扩展 profile 的 26 个工具中有 13 个模拟实现。用例覆盖主要问答行为，但尚未覆盖全部工具与真实数据源。详见 [Golden 设计与执行](Agent_Golden_Evaluation.md)。

### 数据流水线与运维

- 为部分 AKShare 池及 K 线调用增加可终止的子进程超时；来源失败保留缺失或 partial 状态。
- 为生产日更与备份补充时间上限、进程清理及漏日恢复流程，记录 [数据停滞事件与修复](../deploy/incidents/2026-09-29-data-stall.md)。
- 延续不可变预测快照、Outcome 回填和来源感知的复盘边界；本阶段结果不构成评分策略已经具备预测优势的证据。

## 当前限制与下一步

Golden 已具备辅助粗评和问题定位所需的主体功能，可以进入“修 Agent、用固定用例验证”的阶段。它尚不能作为无人复核的发布验收：裁判仍会混淆错误对象/日期与事实矛盾、不完整空查询与确定无记录、独立调用与独立来源；8 项真人抽样也不构成全量签核。

下一步按用户可见影响推进：

1. 修复 `s18` 的回答范围：仅询问评级是否存在时，直接回答该对象与日期，不额外展开其他股票名单；同时验证相邻名单请求不受影响。
2. 修复 `r03` 的失败收尾：业务来源全部失败后，能够诚实说明缺口并结束，减少重复失败查询；核对 `finish` 证据要求，避免部分回答反复被拒。此前六次业务调用不能全部归因于最后两次结束校验。
3. 先跑相关场景及邻近回归，再冻结版本运行新的完整基线；将裁判 review 和已知边界单列复核，保留旧版可比较口径。随后再完善可查日期措辞和高频缺口，不以增加诊断细节替代修复 Agent。

线上真实行情、长会话、多实例运行和评分样本外效果仍需分别验证。项目继续限于数据研究和解释，不提供买卖、仓位、目标价或收益承诺。
