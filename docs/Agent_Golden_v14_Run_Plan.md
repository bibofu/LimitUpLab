# Golden v1.4 冻结与运行计划

本轮仅完成裁判依据、诊断对照及新基线。60个主场景、83个用户回合、固定世界和生产 Agent 保持原定义；人工签核、新盲测、真实行情及跨进程记忆扩展另行推进。

## 冻结前检查

1. 从 Agent 实际模型输入采集白名单运行元数据，两阶段裁判均接收，逐轮保留来源指纹。拒绝输入、缺少元数据或解析失败时不补造。
2. 保留原25条诊断，新增四组共12条对照；标签与证据逐条检查。未知是独立预期，协议异常不能算诊断匹配。
3. 执行 Golden 离线测试和结构校验；随后用同一模型、同一版本完整运行37条诊断两轮，每轮预算72次。保留全部结果，不挑选失败项重跑。
4. 若诊断暴露必须修正的问题，修改后提升裁判版本并重新进行完整校准；旧报告保留。对照标准不随结果放宽。

## 基线执行

冻结代码、题库、固定世界、裁判规则和模型配置后，记录提交及指纹，顺序执行：

- 全部60个场景各一次，调用预算650次。
- 以下12个固定场景各三次，调用预算420次；不根据全量结果换题。

`s02_main_all_heights`、`s17_rating_top`、`s26_single_count`、`s28_star_first_empty`、`m08_clarify_date_pair`、`m09_entity_set_reference`、`m17_memory_is_not_fact`、`r02_partial_source`、`r03_source_error`、`r04_stale_source`、`r09_mixed_research_trade`、`r10_source_truncation`。

预算包含 Agent、记忆和裁判的逻辑调用，SDK隐式重试关闭。预算不是金额上限；实际消耗写入报告。中断仅按相同manifest恢复，不覆盖完整trial。

## 结果验收

- 全量报告具有60个唯一且完整的trial；重复报告具有36个唯一且完整的trial。分别报告pass、fail、review、harness_error及各维度结果。
- 检查两份报告的评测器、生产代码与模型配置指纹相同；题目选择和重复次数按本计划不同。它们不是可直接配对的前后测。
- 对所有非pass及已知边界m08、m17、r03/r04进行逐轮技术复核，保留原始判分。正文漏检单列，不能把自动pass当成人审确认。
- 本次建立的是新测量口径下的基线。v1.3的60/60只作历史记录，不把跨裁判版本分数变化解释为Agent回退或改善。
- 若Agent确有失败，记录为新基线发现；后续生产修复须在冻结的v1.4口径下另跑对照，不在本次运行途中修改代码。

本轮技术复核由Agent完成，`judge_human_calibrated=false`保持不变。
