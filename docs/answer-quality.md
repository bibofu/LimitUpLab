# 回答反馈与人工质量审核

本阶段提供点赞点踩、固定证据包、确定性评审、正常样本抽查和人工审核。当前检测器为 `deterministic-v2`。机器结论和人工结论独立保存；LLM Judge、回归材料导出暂未接入。

## 使用入口

- 聊天回答底部：点赞 / 点踩图标。可改票、撤销，点踩后可选原因及补充说明（最多 1000 字），点击「提交」保存。提交成功自动收起原因面板并保留点踩选中，失败保留面板及内容。刷新会话恢复已有反馈。
- 顶部「质量审核」进入 `/admin/quality`。使用既有 `LIMITUPLAB_ADMIN_KEY` 登录；密钥只放在页面内存，不进入 URL、本地存储或前端构建产物。
- 审核页支持状态、来源、严重程度、症状和运行版本筛选。选择案例后查看问题、上下文、正式答案、工具结果、模型输入视图、交付记录与审核历史。
- 案例详情新增「确定性评审报告」：查看每次尝试的执行状态、逐项结论、证据路径和未知原因。最近人工审核之后出现新信号时显示提示，原审核状态和修订号不会被机器改写。
- 当前鉴权是共享管理员密钥，审计身份记作 `admin`；负责人是分派字段，不代表独立身份认证。

## 启动检测 worker

从项目根目录另开终端：

```powershell
.\backend\.venv\Scripts\python.exe backend/scripts/run_quality_worker.py --interval 10
```

单次处理：

```powershell
.\backend\.venv\Scripts\python.exe backend/scripts/run_quality_worker.py --once --limit 20
```

Docker Compose 已增加 `quality-worker` 服务，与后端共用同一 SQLite 数据卷。部署时一并构建、启动该服务。审核页的「处理一批检测任务」每批手动运行最多 20 个确定性任务，API 单次上限为 50 个，不调用模型。

从 v1 升级时先停止旧 worker，再启动新版后端和 worker；不支持旧二进制持续轮询新任务表。迁移在事务内完成，重复初始化安全；迁移失败整体回滚。旧任务和案例保留，旧未完成任务标记为 `superseded`，旧租约失效。旧版没有完整评审报告的记录明确标为 `skipped/unknown`，不会补造历史通过结论。

| 配置 | 默认值 | 含义 |
|---|---|---|
| `LIMITUPLAB_QUALITY_NORMAL_SAMPLE_RATE` | `0.05` | 正常终态运行的稳定抽样比例，范围 0～1 |
| `LIMITUPLAB_QUALITY_TRACE_RETENTION_DAYS` | `30` | 附加私有诊断快照的保留天数，范围 1～3650 |
| `LIMITUPLAB_QUALITY_EVALUATION_TIMEOUT_SECONDS` | `30` | 确定性评审时间预算，范围 1～300 秒 |
| `LIMITUPLAB_BUILD_REVISION` | 空 | 可选发布提交号或标签；同时保存应用源码指纹 |

抽样由运行 ID 和检测器版本生成稳定桶值，配置在入队时固定。改变环境变量不会自动重评已经排队或完成的运行；管理员可显式用新抽样比例创建新任务。查看队列中待处理、执行中、已完成、失败待查数量，可判断 worker 是否在工作。

## 状态与审核

执行状态、任务结果、交付状态、人工质量结论分别保存或派生。`complete` 表示 Agent 的任务交付声明，不表示通过人工质量复核。

主流程：待复核 → 已确认 → 修复中 → 待验证 → 已关闭。支持非缺陷、证据不足、重复案例及重新打开；重复案例必须关联一个存在的非重复案例，不允许形成循环或链式重复关系。

确认问题需填写症状；进入待验证或关闭前需填写根因和修复版本。每次保存都要求审核说明，并追加变更记录。并发审核采用修订号校验，旧页面提交返回冲突，重新载入后再审核。重新载入会以服务端记录替换未保存草稿。

已关闭表示问题处理完成，原回答仍是曾经确认的问题。撤销点踩不会删除既有案例和审核历史。严重问题在审核说明中记录影响、停用或回滚措施；当前实现不自动修改系统配置或发布版本。

## 确定性评审

每次尝试分别保存任务执行状态（`running/succeeded/error/skipped`）与检查结论（`pass/fail/unknown`）。执行失败和跳过都只能是 `unknown`；一项明确失败使报告为 `fail`，没有失败但存在未知项时报告为 `unknown`。`pass` 仅说明已记录的结构检查通过，不代表自然语言完全正确。

| 检查 | 可以确定的内容 | 不能据此认定 |
|---|---|---|
| 保存一致性 | 正式答案、会话消息、最终检查点和采集后摘要是否一致 | 浏览器一定展示或用户一定阅读 |
| 引用和计数 | 正式候选的本轮证据引用、完整返回行数和声明计数是否一致 | 查询是否覆盖用户真正想要的全部范围 |
| 重复事件 | 完整涨停事件中同股票、同交易日是否重复 | 不同日期出现同股票属于错误 |
| 日期契约 | 显式单日工具参数与工具声明的日期是否一致 | 模型选择的日期一定符合用户语义 |
| 终态契约 | 已交付 finish 状态、缺失说明和证据状态是否矛盾 | 模型声明 complete 就完成了全部需求 |
| 表格渲染 | 用原始候选、已保存证据和同指纹代码能否重放出原答案 | 自由正文中的事实和来源正确 |
| 纯计算 | 基于完整父证据同版本重算派生结果是否一致 | 来源数据本身符合市场事实 |

引用、计数、日期和计算只检查最终使用的证据及其父证据，不将一次被修复的中间尝试当作正式错误。表格/计算遇到历史证据、缺失、脱敏、截断、未知结构或代码指纹不一致时保留未知；缺少表格或计算时相应检查也明确标注不适用。保存副本的一致性独立检查，不会因正式候选关联失败而跳过。

评审之外仍保留以下人工线索：

- 最终执行失败：记录失败类型和停止原因；工具中途失败后成功恢复，不单独判整轮失败。
- 部分完成、主动取消：低严重程度线索，人工判断是否存在问题。
- 引用和行数据：仅对能确认属于正式交付的结构化终态，检查本轮证据引用、明确工具契约下的返回计数、同股票同交易日的重复涨停事件。
- 断线：客户端在本次请求被受理后报告中断；可能未取得最终答案，此时回执不包含答案摘要。后续正式答案的接收/展示回执覆盖中断状态。
- 正常抽样：没有其他异常信号的正常终态按配置抽样，避免只检查投诉样本。

这些规则不扫描自由正文推断事实正确性，也不覆盖全部语义错误。没有浏览器回执保持未知，不能推断用户没看到答案；有展示回执不能证明用户已阅读。完全断网、页面突然关闭时回执可能无法送达。历史记录缺少证据或版本时，不补造这些信息。

## 固定证据与任务基础

`quality_evidence_bundles` 保存不可变证据包，`quality_evaluations` 保存每次尝试的报告；已有反馈、交付、案例、信号、审核、任务和诊断表继续使用。没有疑似案例的 pass/unknown 结果仍有报告。

正式回答、证据包和检测任务在同一事务中提交。包包含请求、运行开始前的同会话上下文、正式答案与消息副本、工具原始结果、检查点、模型输入/输出关联、版本指纹及渲染输入。manifest 保存原答案摘要、采集后答案摘要、内容摘要、时间、捕获方式和遗漏清单。后续重试与新配置评审复用原包；诊断快照被清理也不会改变原包。历史补扫明确标注 `historical`，不会伪装成回答完成时的现场。

每次模型调用使用独立 ID 关联输入和返回；尝试发起不等于已收到响应。浏览器回执通常晚于证据冻结，因此评审另存本次领取时的交付观察，不把后续回执写回原包。

worker 按任务类型和检测器版本领取，按类型、版本、配置摘要和包 ID 幂等去重。租约定期续期，完成事务再次验证 token 和过期时间；每次失败均有独立 unknown 报告，最多重试三次。时间预算在规则间和重放循环中检查，属于协作式超时，并非强制终止任意第三方代码的进程隔离。

预留 `llm_judge` 任务类型及 `quality_budget_usage/quality_budget_reservations` 原子预算接口；当前无 Judge worker、无 Judge 入队 HTTP 接口，也不调用评审模型，模型调用和 token 用量为零。未来 Judge 需要独立接入预算、模型执行和输出校验。

## 管理 API

以下请求均需 `X-LimitUpLab-Admin-Key` 请求头：

| 方法与路径 | 用途 |
|---|---|
| `GET /api/admin/quality/evaluations` | 全部尝试，可按 `verdict`、`execution_status` 筛选，包含未生成案例的运行 |
| `GET /api/admin/quality/runs/{run_id}/evaluations` | 某轮运行的评审历史 |
| `GET /api/admin/quality/bundles/{bundle_id}` | 读取脱敏后的固定证据包 |
| `POST /api/admin/quality/runs/{run_id}/evaluations` | 显式入队当前确定性版本，可传 `normal_sample_rate`、`bundle_id`；相同配置返回已有任务 |

历史列表支持 `limit/offset`。前端本阶段在案例详情提供报告只读展示；全量报告、包读取及显式重评通过上述 API 操作。

## 隐私和生命周期

模型输入快照记录工具返回给模型的视图，工具结束快照和已有 Journal 保留原始结果，二者不可混为一谈。超出采集上限时保存明确的截断或省略标记。凭据字段与已配置密钥在附加快照采集及管理读取时脱敏；任意自然语言中的个人信息仍需要维护者审慎处理，不把原始诊断记录提交到 Git 或外发。

证据包单个区域上限 2 MB、正文总量上限 4 MB，超过上限整体省略区域并记录原因，不截取残片当作完整证据。诊断解析或采集失败时保存最低限度的 unknown 包及异常类型，正常答案仍能落库；数据库提交失败则整体回滚，不能出现答案保存但任务丢失。

worker 清理过期的附加诊断快照；固定包随会话保留，不受诊断 TTL 清理。用户删除会话时，关联反馈、诊断、证据包、评审尝试、任务、案例和审核记录一并级联删除；已消耗预算的匿名累计数不返还。本阶段不另外保留匿名案例副本。预测快照和 Outcome 等业务记录不由该功能修改。

## 验证

测试覆盖反馈归属、冻结与哈希、诊断失败隔离、历史迁移与回滚、并发初始化、三态检查、同包重试、租约恢复、预算竞争、信号与报告原子提交、保留人工审核和删除级联。前端覆盖提交字段白名单、会话切换、回执绑定及审核转换，并执行生产构建。实际验收使用隔离数据库和真实 Agent；测试报告与数据库只保留在忽略目录，不作为线上质量统计。

2026-10-17 验收：819 项相关后端回归通过，最后边界修正后 114 项质量专项通过；230 项前端测试与生产构建通过。真实三个简单问题均 complete/answered，固定证据、输入关联、后到回执独立保存、同包幂等和人工审核关闭通过。现有依赖弃用及前端包体积提示仍存在。
