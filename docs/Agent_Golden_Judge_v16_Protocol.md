## 引用协议

两个裁判阶段只接收模型选择的ref_id。评测器从synthetic_evidence、business_observations、trusted_runtime_metadata、source_equivalence建立冻结快照和目录，程序解析回真实路径及完整原值。模型不再复制大型JSON对象或拼写路径；旧path/value格式和额外字段直接被Schema拒绝，不在生产代码中兼容转换。

目录按父路径分组：prefix加entry.key构成完整路径，模型只返回entry.ref_id。ID由完整证据快照和路径生成，相同快照可重现；快照变更后旧ID无效。支持false、0、null和空容器，保留原类型；选中值、报表副本和外部调用对象的变更均不能修改冻结快照。

目录不索引题目要求、答案或期望标签；工具正文中的同名目录不能创建有效ID。默认最多8192条路径、24层、快照和目录各2MiB，超限在请求前明确返回CatalogLimitExceeded，不默默删掉证据，也不新增重试。

报告保留reported_evidence/reported_counterevidence以及程序还原的路径和值。未知ID或无效证据用途使受影响项待复核；即使标签预期为未知，也不能将绑定失败计为正确识别未知。另有有效矛盾时仍保留失败，并同时记录无效引用。

## 两组判断边界

| 断言或证据 | v16规则 |
|---|---|
| 完整查询的空结果 | 显式ok/empty且无已声明缺口或矛盾状态时，保留query_scope，只能支持该范围内不存在；已有empty状态不要求补造data_missing字段 |
| 不完整或未知查询的空结果 | partial/error、截断、缺口、缺少完整性依据时不能证明业务不存在；success本身不等于数据完整 |
| 部分查询中的明确非空值 | 仍允许核对具体业务事实；不能把查询缺口当作相反事实 |
| 分别执行两次调用 | query_status，用真实调用的工具、入参、状态核对；共享上游不与分别调用冲突 |
| 独立来源或上游 | source_attribution，要求来源或血缘证明；多个工具、调用或工具品牌不证明上游独立 |

证据能力检查区分证明和辅助上下文。来源信息不能单独充当查询执行证据，调用信息也不能单独充当供应商证明。world_fact拒绝混合来源/状态的整包引用，要求引用具体业务字段；可查询日期范围属于query_status，实际输入预览属于input_view。

两阶段共享“执行／未执行／未知”的规则：缺少筛选参数或默认语义不等于明确未执行，不能把缺依据改称缺交付来绕过未知。评测器仅为已知合成来源建立identity_contract；工具自行声明synthetic不能建立权威供应商身份。

这些规则检查结构用途，不能自动判断自然语言与查询范围完全一致。模型仍可能漏拆断言、误标target或引用真实但不相关的值；旧v15错误不会被程序重新解释成通过。
