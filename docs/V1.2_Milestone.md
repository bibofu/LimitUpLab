# LimitUpLab V1.2 阶段里程碑

> 原始标签：`v1.2.0`（历史基线）
>
> 当前口径更新：2026-09-07

## 1. 当前定位

LimitUpLab 已收敛为面向已经发生涨停股票的收盘后研究平台：策略引擎提供可审计结果，Agent 提供统一查询、筛选、解释、比较和复盘入口。

旧实验由 Git 历史与本地清理前备份保留，不再提供运行时兼容接口、前端入口、Agent 工具或日更任务。

## 2. 双核策略平台

策略核按固定顺序注册七项策略：

1. 一进二接力：`forward_validation + ranked_research`。
2. 高位回撤：`exploratory + observation_pool`。
3. 横盘缩量：`exploratory + observation_pool`。
4. 回撤企稳：`exploratory + observation_pool`。
5. 强势不连板：`exploratory + observation_pool`。
6. 断板修复：`exploratory + observation_pool`。
7. 二进三：`exploratory + observation_pool`。

所有候选必须具有真实涨停锚点、策略版本、数据截止日、证据和缺失项。排名策略冻结 Top10；探索策略冻结无名次观察池，不展示概率、胜率承诺或跨策略总榜。

Agent 核通过同一注册表回答策略目录、最新结果、单股路径和策略统计问题。跨策略比较同时展示样本量、完整度、时间范围与风险指标；不满足可比门槛时拒绝优劣结论。Agent 不创建临时分数、不修改权重、不登记 Challenger。

## 3. 数据闭环

- 通用 `strategy_runs`、`strategy_candidates`、`strategy_outcomes` 保存版本化不可变结果。
- 每日收盘后冻结首次可观察信号，持续符合不重复冒充新信号。
- D+1、D+3、D+5 按实际交易日精确对齐，缺 K 线保持未就绪。
- 一进二历史预测、Outcome、复盘快照和评分策略记录在旧实验清理中保持不变。
- Champion/Challenger 仅服务具备排名资格的策略，并继续要求至少 60 个成熟 Outcome 日、样本外提升和风险不退化。

## 4. 产品接口

```text
GET /api/strategies
GET /api/strategies/{strategy_id}/latest
GET /api/strategies/{strategy_id}/history
GET /api/strategies/{strategy_id}/stocks/{symbol}
GET /api/strategies/{strategy_id}/statistics
```

前端推荐页已重构为策略列表，策略详情统一包含候选、单股路径、历史统计和方法说明四区。推荐情报只保留一进二 relay 数据结构。

## 5. 已知边界

- 一进二仍处于前向验证，尚未证明可以稳定提高后续表现。
- 六项探索策略需要继续积累不可变前向样本，未达到排名资格。
- 本地数据来源可能延迟或缺失，完整度必须与描述性指标同时展示。
- 当前部署适合 SQLite 单机与有限并发；横向扩容仍需独立数据库、缓存和任务队列。
- 本项目只做研究解释，不构成投资建议。

## 6. 里程碑结论

这次演进的完成标准不是增加策略数量或短期调参，而是让“真实涨停锚点 → 注册策略 → 不可变信号 → 精确 Outcome → Agent 解释与复盘”形成可信闭环。
