# LimitUpLab V1.2 阶段里程碑

> 记录日期：2026-09-01
>
> 里程碑标签：`v1.2.0`
>
> 代码基线：以 `v1.2.0` 指向的提交为准

## 1. 版本定位

V1.2 是一次工程收敛版本。它没有继续扩张盘中能力，而是回到 LimitUpLab 最可信、最容易审计的产品边界：使用完整收盘数据形成一进二 Top10 研究候选，保存不可变预测快照，并持续追踪 D+1 至 D+5 结果。

V1.1 的集合竞价实验仍由 `v1.1.0` 标签完整保留，但不再进入当前主线。V1.2 将另一条策略调整为“低位挖掘观察池”，用于研究热门题材、新闻财报和低位走势的交集，不把它伪装成次日首板预测。

本项目继续用于数据研究、Agent 工程实践和作品展示，不构成投资建议，不输出买卖指令、仓位、目标价或收益承诺。

```text
完整收盘数据
  -> 一进二 Top10 不可变预测
  -> D+1 至 D+5 Outcome 回填
  -> 市场与简单规则基线对照
  -> Review / Evaluation 复盘
  -> 受约束的评分改进建议

热门题材 + 新闻财报 + 60 日 K 线
  -> 低位挖掘观察池
  -> 独立前向验证
```

## 2. 本阶段完成内容

### 2.1 恢复收盘后预测主线

- 删除集合竞价采集、存储、评分、终选 Worker、接口和过时诊断代码，降低数据源不稳定带来的运行复杂度。
- 一进二候选恢复为收盘后固化 Top10；推荐页面、Agent、Outcome、Review 和 Evaluation 读取同一批不可变快照。
- 一进二候选排除创业板，并修复过滤后名次不连续、旧动态分影响最终排序等问题。
- 对动态调整建立信息截止契约：收盘前已公开的新闻和财报进入收盘综合分，盘后新增龙虎榜、人气变化、新闻公告只能作为带时间戳的盘后修正。

### 2.2 低位挖掘替代首板预测

- 不再直接推荐“可能涨停的 Top10”，改为数量不固定的低位启动研究观察池。
- 先从热门概念、行业和新闻催化召回股票，再使用最新财报和至少 60 根日 K 线验证。
- 排除近期涨幅过大、接近 60 日高位和二波高位结构的样本。
- 每只候选按“题材、新闻和财报、走势”展示证据，并明确研究排序不等于主升浪或收益概率。

### 2.3 Agent 原生 Function Calling

- Planner 通过 OpenAI-compatible 原生 Function Calling 调用 `submit_agent_plan`，由函数参数承载能力、上下文关系和工具计划。
- Capability Contract 成为业务工作流的统一声明源，同时约束 Planner Schema、Tool Policy 和执行器。
- Query Contract 继续确定性提取日期、市场、板高、状态、排序和数量，避免 LLM 改写用户明确条件。
- 不支持 Function Calling 的兼容 Provider 可以回退到 Prompt-to-JSON；工具失败和 LLM 不可用时继续使用事实一致的降级回答。

### 2.4 滚动 Session Memory

- 会话保留最近原始消息，并将离开窗口的历史消息滚动压缩为结构化记忆。
- Memory 记录研究目标、股票实体、日期范围、用户约束和未解决问题，按 `owner_id + session_id` 隔离并持久化到 SQLite。
- Memory 只用于维持对话连续性，不作为价格、新闻、评分、排名或市场状态的证据；相关问题仍必须重新调用结构化工具。
- Function Calling 不可用或 LLM 故障时具有兼容降级，记忆刷新失败不会阻断用户问答。

### 2.5 个股行情加载优化

- 个股详情合并重复市场数据请求，减少页面首次加载时的重复数据库查询与远端调用。
- 日 K、分时、量比和派生指标复用统一缓存结果，保持展示口径一致。
- 热缓存请求可以直接从本地数据返回，为后续公开部署下的并发访问降低延迟和外部数据源压力。

## 3. V1.2 的核心价值

V1.2 的价值不是宣称评分更准，而是让项目更诚实、更稳定，也更像一个可解释的 Agent 工程作品：

1. **预测口径可审计**：明确使用什么时间点的数据、保存哪一批正式预测、复盘评价哪次输出。
2. **LLM 职责清晰**：模型负责理解、规划、解释和总结；过滤、评分、统计与事实读取由确定性代码完成。
3. **多轮对话可持续**：滚动记忆解决固定截断后的上下文丢失，同时不允许记忆替代最新工具事实。
4. **策略实验彼此隔离**：一进二 Top10 与低位挖掘使用不同目标、快照和 Outcome，不混合计算准确率。
5. **运行成本更可控**：删除不稳定竞价链路并优化行情加载，为本地和单机部署减少故障点。

## 4. 已知边界

- 当前评分仍未证明可以稳定提高一进二成功率；已有诊断结果必须与市场和简单规则基线共同展示。
- 可用于严格样本外评价的完整 Outcome 交易日仍有限，不能依据少量日期自动修改线上 Champion 权重。
- 低位挖掘尚未形成足够长的独立前向 Outcome，不能宣称能够预测主升浪。
- 新闻、财报、龙虎榜和人气数据存在来源延迟与缺失，所有动态修正都需要保留来源时间和缺失标记。
- 当前部署基线适合单机与有限并发；横向扩容仍需要 PostgreSQL、Redis 和后台任务队列。

## 5. 下一阶段方向

1. 持续积累每日一进二 Top10 的完整 D+1 至 D+5 Outcome，并与全市场、最早封板和固定随机基线比较。
2. 为低位挖掘建立独立的前向 Outcome、候选池基线和分层复盘，验证题材、催化与位置特征是否具有增量价值。
3. 将 Agent 自动评测扩展为可公开展示的报告，覆盖改写、多轮上下文、工具准确率、事实完整性和三轮稳定性。
4. 完善演示流程、架构说明、截图和部署文档，让项目可以在 3 至 5 分钟内被面试官理解。
5. V2 再评估稳定实时行情、更多策略和盘中研究能力，继续沿用不可变快照、信息截止、Outcome 和审计协议。

## 6. 里程碑结论

`v1.2.0` 标志着 LimitUpLab 从功能扩张转向工程收敛。项目保留了真实数据、可解释评分、不可变预测、结果复盘和工具型 Agent 的核心闭环，同时明确撤下尚未证明可靠的集合竞价链路。这个版本不承诺预测市场，却提供了一套可以持续积累证据、主动证伪假设并安全演进的研究系统基线。
