## 规则与协议

- 最终交付逐条绑定原要求。“A或B”允许任一有依据的分支；没有要求工具名、异常类或技术原因时，不能把它们追加为交付条件。
- 正确说明查询失败，可以满足对应说明要求。额外编造的故障原因由可见事实审查或明确要求该内容的标准处理，不连带否定其他已完成的单项交付。
- 两阶段均先给简短依据，再给判定。来源审查逐项检查完整来源短语，工具标签本身不能证明供应商，合法来源ID不能抵消额外的错误归属。
- 交付负判必须引用本条原要求，并区分缺交付、违反要求、事实矛盾。后两类必须引用最终正文；事实矛盾还须引用反证路径及原值。
- 可见事实或来源判为矛盾时，必须同时定位回答原文和反证。代码核对路径、JSON类型及值；允许零、false、null和空数组保留原义，不按字段名猜测业务含义。
- 无效引用保留原判、原理由和校验错误，转为待复核，不能计为正确识别了未知。没有按题号、供应商关键词或正则覆盖判定。

这些门禁只能证明引用真实存在，不能证明引用与断言逻辑矛盾；原要求引用也不能完全消除语义误解。模型校准和独立复核仍然必要。
