# LimitUpLab 任务清单

本文件用于跟踪 LimitUpLab 从“涨停复盘看板”升级为“可解释首板评级 Agent 系统”的开发进度。
后续每完成一个阶段，都要同步更新本文件状态。

状态说明：

```text
[ ] 未开始
[~] 进行中
[x] 已完成
[!] 阻塞 / 需要决策
```

## V1.0 收尾路线（2026-08-29）

V1.0 最终定位：使用完整收盘数据，为最新交易日首板生成次日一进二 Top10 观察候选，并持续回填 D+1 至 D+5 结果。V1.0 可按需读取带时间戳的热股榜、行业强弱榜和东方财富、同花顺财经快讯，但不把它们用于评分；盘中、集合竞价、通用网页搜索和其他策略不属于 V1.0。

- `[x]` 固化 V1 Agent 能力边界。
  - 默认配置为 `LIMITUPLAB_AGENT_PROFILE=v1_close_review`。
  - Planner Schema 只暴露收盘后研究工具。
  - Skill Registry、Tool Policy 和执行器使用同一工具白名单。
  - 即使 LLM 直接生成禁用工具调用，执行器也会拒绝。
  - 保留 `extended` 配置供 V2 开发和既有扩展能力回归测试。

- `[x]` 增加 V1 范围自动评测。
  - 覆盖盘中板块、盘中价格、集合竞价、公司最新新闻和通用网页搜索等越界问题，并验证热股榜、收盘行业强弱与综合财经快讯可基于结构化来源回答。
  - 越界问题在调用 LLM 前返回统一的无法回答提示，避免模型用旧数据或常识拼凑答案。
  - 覆盖错误 Planner 注入禁用工具的服务端拦截。

- `[~]` 完成 V1 产品口径统一。
  - README、需求和 V1 里程碑统一为收盘后首板一进二研究工具。
  - 所有推荐页面和回答明确数据截止交易日，不使用“实时”“当前”等误导表达。
  - 评估是否将“盘前推荐”统一改名为“次日观察”，使产品文案与非交易建议边界一致。

- `[x]` 完成 Top10 预测链路验收。
  - 每个交易日只生成一份不可变 `live` Top10 快照，重复任务必须幂等。
  - 页面、Agent 和复盘统一读取同一份预测快照，不允许临时重算替代历史预测。
  - Top10 必须记录评分版本、完整 Facts、缺失字段、置信度和数据截止日期。
  - 新增 `agent_live_prediction_snapshots`，整批响应与逐股预测在同一事务中写入。
  - Schema v2 会为旧库保留每个交易日最早的 live 批次，并移除后续评分版本产生的伪重写记录。
  - 日更重复执行实际新增数为 0；推荐 API、Agent 工具、Review、Evaluation 和质量审计按完整日批次读取。

- `[x]` 完成 Outcome 完整性验收。
  - 对已成熟预测自动补齐 D+1 晋级和 D+1 至 D+5 走势。
  - 高分票追踪不得静默展示缺失缓存；缺失必须进入数据健康和任务告警。
  - 独立展示 Top10 一进二成功率、全部首板基线和简单规则基线。
  - 新增统一 Outcome 完整性报告，逐交易日列出 D+1、D+3、D+5 成熟度、覆盖数和缺失股票。
  - Outcome 严格对齐市场交易日期，缺少 D+1 时禁止使用 D+2 K 线冒充次日结果。
  - 日更任务只追踪持久化预测，并在 20 个交易日重试窗口内持续补齐已经滑出近期展示范围的缺口。
  - 完整性结果进入日更报告、数据健康、Review 告警和受保护的管理接口。

- `[ ]` 完成 V1 最终验收。
  - 使用固定历史日期回放完整日更、评分、快照、Outcome、复盘和 Agent 问答链路。
  - 运行完整后端测试、Agent Eval、前端生产构建和生产健康检查。
  - 验收通过后记录 V1 收尾报告，并创建后续版本标签。

  -> 前端首板评级页

```text
Critic Agent
  -> Evaluation Agent

  -> 项目包装
```

## Milestone 1：首板评分 Agent MVP

目标：系统可以基于真实涨停数据筛出当日首板，并给出可解释评分。

- `[x]` 实现首板候选池过滤。
  - 支持传入 `trade_date`，默认使用最新交易日。
  - 只保留 `board_height = 1`。
  - 只保留 `closed_limit = true`。
  - 排除 `ST / *ST / 退市风险警示` 股票。
  - 排除北交所股票。
  - 排除科创板股票。
  - 排除新股 / 次新股。
  - 排除成交额过小样本。
  - 缺失过滤字段时标记为 `data_missing`，并降低 `confidence`。

- `[x]` 实现首板候选 facts builder。
  - 从已有涨停事件和市场汇总中构建结构化事实。
  - 包含首封时间、炸板次数、封板次数、换手率、成交额、行业、市场环境、行业热度。
  - 不让 LLM 编造任何行情字段。

- `[x]` 实现规则评分引擎。
  - 输出 `score`、`rating`、`confidence`、`score_breakdown`、`reasons`、`risks`。
  - 明确区分 `score` 和 `confidence`。
  - 评分结果必须可解释、可测试、可复盘。

- `[x]` 完成首板评分扩展输入 v2。
  - 为当日合格首板候选缓存截至评分日的最近 60 日 K 线，并派生 5/20/60 日涨幅、距阶段高点、量比、波动率和均线结构。
  - 接入 CNInfo 上市日期，计算上市天数并用于新股/次新股过滤。
  - 流通市值优先使用龙虎榜明细真实值，缺失时使用成交额/换手率估算并记录来源。
  - 从个股 60 日 K 线按主板约 10%、创业板约 20% 的涨停阈值识别近 20/60 个交易日涨停次数，不依赖涨停池历史接口的保留期限。
  - 细化行业首板数、连板数、炸板数、板块高度、首封位次、昨日首板晋级率和市场首板封住率。
  - 接入东方财富龙虎榜和人气 Top100 时点快照；接口失败可降级并写入 `data_missing`，不编造数据。
  - 新增 `first_board_enrichment_snapshots` 时点快照表，评分版本升级为 `first-board-rule-v2-enriched`。
  - 2026-08-13 实测：32/32 候选具备 60 日 K 线、上市日期和流通市值，8 只命中龙虎榜，14 只进入人气 Top100。

- `[x]` 增加首板股票位置判断 v1。
  - 将候选 K 线窗口扩展到最多 120 个交易日，严格只使用首板当日及以前的数据。
  - 可解释分类覆盖超跌反弹、V形反转、低位启动、中位平台突破、趋势加速、高位震荡、高位突破、二波启动和结构不明。
  - 输出主类型、匹配度、次选类型、辅助标签、判定证据和底层指标，并随 enrichment 固化进不可变预测快照。
  - 位置分类暂不直接改变评分权重，先由 Review Agent 统计不同位置类型的后续兑现差异。
  - 首页 Top5 评分卡展示位置判断；个股详情通过独立位置接口展示，不依赖当天首板评级池。
  - Agent 问答支持按首板前 K 线位置完整分类评级候选池，并校验所有类别和候选均被回答覆盖，避免将“位置”误解为首封时间。

- `[x]` 增加每日连板晋级率统计。
  - 以前一交易日收盘封住的涨停股票为样本，下一交易日仍封板且板高恰好增加一板时记为晋级。
  - 分别统计全部涨停样本、首板到二板、已有连板继续晋级，以及各板高梯队的样本数、晋级数和经验概率。
  - 首页展示最近 5 个有效交易日的晋级率、样本量、日间变化和板高梯队。
  - 5 个交易日作为可点击选项，选中后展示当日全部晋级成功股票，并可进入个股详情。
  - 新增 `GET /api/analysis/daily-promotion` 和 `daily_board_promotion` Agent 工具，问答必须引用逐日样本数，不能根据单日涨停数量推测晋级率。
  - 本地相邻数据日期间隔超过 4 天时跳过该组，避免把明显的数据断档当作连续交易日。

- `[x]` 新增首板评级 API。
  - 建议接口：`GET /api/agents/first-board-ratings`。
  - 支持日期参数和最新日期 fallback。
  - 返回候选事实、评分拆解、理由和风险。

- `[x]` 增加后端测试。
  - 测试候选池过滤语义。
  - 测试评分区间和评级标签。
  - 测试缺失数据会降低置信度。
  - 测试输出不包含买入、卖出、目标价、仓位等投资建议表达。

验收标准：

```text
后端能返回某个交易日的首板评级列表。
每只股票都有分数、评级、置信度、评分拆解、理由和风险。
测试通过。
```

  - 请求包含 `session_id`、`message`、`trade_date`、可选 `symbol` 和页面上下文。
