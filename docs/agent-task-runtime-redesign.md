## 目标与边界

让已有工具支持的问题能按用户约束完成；工具或模型不可用时保留已获得的证据，明确未完成项。
新问法、新实体、新参数和已有能力的新组合，不应要求新增 scenario 分支。
不保证回答无限领域的问题。未支持的能力、歧义和超预算请求必须得到明确说明。
本次研究型 Chat 改造不改评分算法、历史预测快照或市场数据，不改变投资合规边界。

## 设计决定

### 一份任务契约贯穿全链路

引入独立的 RequestContract，包含 request_id、anchor_datetime、用户原文、上下文引用及 requirements。
每项 requirement 有稳定ID、交付目标、实体作用域、时间作用域、数量/排序/过滤、来源原文片段。
明确区分自然日、交易日、截至日、事件日、结果成熟日；相对时间由交易日历和锚点确定性解析。
问题明确约束优先于页面默认值；多轮明确修改可覆盖已继承约束，必须记录被修改字段。
不同子任务的limit、days、date互不共享。用户约束不得被Replan为获得成功结果而放宽。
LLM负责语义拆解；代码检查类型、引用、取值、日期和来源片段。语义覆盖检查仍有误差，不能声称代码可证明自然语言理解完全正确。

### 计划与任务分开

TaskPlan包含有唯一step_id的步骤，分别关联requirement_ids。
步骤声明tool、typed arguments、depends_on、条件及结构化result references。
允许同一工具以不同参数重复出现在计划中；缓存复用依据规范化调用指纹和数据时点，不按工具名去重。
结果引用限定为前序步骤及已注册输出字段，不允许eval、任意脚本或不受控表达式。
通用集合操作包括排序、取前N、筛选、交集和逐实体展开；业务指标仍由现有服务确定性计算。
实体集合为空时记录合法empty，不把它转换成空股票参数的工具调用。

### 统一LangGraph运行时

所有受支持Chat请求进入同一状态机。单步与多步由计划结构体现，不设问法白名单。
流程：理解/计划 → 验证 → 执行就绪步骤 → 观察/完成检查 → 必要时LLM修订 → 证据回答。
互相独立的步骤可受限并发，依赖步骤等待结果；只有必要的信息变化或缺口才调用Replanner。
正常依赖展开是执行，不计为Replan；原样重试、参数修订、策略补查分别计数。

LLM Replan输入：原始要求、计划版本、执行历史、具体失败、证据摘要、未完成项、剩余预算。
输出为类型化计划patch及原因，只允许添加/替换未完成步骤、明确澄清或报告无法完成。
patch必须通过工具授权、参数schema、依赖无环、证据引用、重复请求和预算检查。
已成功的结果不可静默删除或覆盖；新事实冲突时并存并标明时点/来源，由回答披露。
即使LLM认为应结束，未交代的requirement也使最终状态保持partial，而非complete。

### 工具适配器只消费已验证参数

将自然语言提取、页面默认值处理从执行适配器移到执行前的契约解析层。
适配器不再阅读整句问题决定日期/股票/模式，不再静默clamp用户明确参数。
不支持的窗口返回明确validation_error/unsupported_constraint，交给规划层解释或澄清。
工具注册表公开参数、输出schema、最大返回量、分页、数据时点与可用范围。
要全部名单时必须遍历分页或披露截断；cannot_return_all不能标为名单完成。
底层原始服务可复用，但不能未经适配审查直接套用旧handler。

### 不可变执行证据与双重完成检查

ExecutionRecord以call_id、step_id、requirement_ids索引，记录requested/resolved/actual参数。
保存result_state、实际实体/时间范围、完整度、来源、证据路径、耗时、错误类别与重试次数。
取回原始结果和给LLM的摘要分离；摘要裁剪必须显式标记，缺失细节可按证据引用读取。
关键事实使用entity/date/metric/value/source引用，支持同值不同指标、跨股票和日期错绑检测。

执行完成：必要调用及所有目标实体均有结果，实际参数满足契约；empty/error各有明确状态。
回答完成：每项交付要求被有效回答、说明不可得、等待澄清或显式标记未完成。
二者独立，工具调用成功不意味着任务完成，答案有段落也不意味着事实正确。

### 按任务生成与修复答案

AnswerPlan为每项requirement分配段落，段落引用ExecutionRecord的证据。
确定性呈现关键数字、名单、排序和覆盖状态；LLM负责有依据的解释、联系和总结。
检查不通过时只修订相关段落，复用其他已通过段落；全局安全风险则不给出危险内容。
兜底渲染按requirements遍历证据，不能使用首个匹配工具就return的单工具优先级链。
历史买卖事实、引用和否定表述，与面向用户的交易指令分别处理；禁词只作风险信号。
安全语义检查接受结构化证据类型，补充建议对象/意图判断；校验不可用时只呈现安全事实和缺失说明。
不能将LLM判断视为安全或Grounding的唯一保证。
可先发送工具进度，事实段验证后再流式发送；段落修订应显式标识，避免整答闪现后无提示替换。

## 高可用约束

- 完成、部分完成、需澄清、能力不支持、超时、取消、配置错误必须是不同终态。
- 每次请求有总deadline；模型、工具有独立超时及取消传播；剩余预算不足时停止新增工作。
- 暂定总工具预算沿用产品8次，LLM Replan最多2次；所有失败重试也计入预算，配置集中管理。
- 全量动态集合超过预算时优先已注册批量/分页能力，否则明确覆盖边界，不静默少查。
- 临时网络错误允许有限退避重试；参数错误先修订；合法empty不自动重试；配置错误不反复调用。
- 缓存键含参数、数据版本与时点，跨用户上下文不串用；当前行情不能无限复用旧缓存。
- 会话checkpoint保存计划版本和执行状态，重复HTTP/SSE重连复用同一run，不重复发起付费执行。
- Provider超时不破坏已完成证据；有证据时给完整的分任务兜底，无证据时明确不可用。
- 输出控制模型调用数、产品token、首响应/最终响应p50/p95、错误率、恢复率和任务完成率。
- 不把“返回HTTP 200”或“没有异常”作为业务成功。

## 迁移与验收

1. 契约与证据层：建立类型和不变量测试，逐个适配现有工具，验证actual参数等于已解析约束。
2. 通用执行层：替换场景图，接入LLM初始计划及真实LLM Replan；独立测试依赖和patch校验。
3. 回答层：接入分任务合成、局部修复及无损兜底，替换旧全局单工具降级链。
4. 真实验收：冻结工具world测试模型规划；生产工具+真实HTTP/SSE检查参数、事件、答案一致。
5. 切换：达到门禁才成为默认；迁移期开关必须标识实际运行版本，完成后删除无消费者的旧路径。

十个旧问题仅作为回归，不修改Golden迁就实现。另设未见组合和措辞改写作为盲测。
每类都覆盖多个日期、实体、TopN、多窗口、同工具多调用、反向任务顺序和多轮继承。
故障注入覆盖empty/partial/error、模型计划畸形、依赖循环、摘要截断、重复调用、取消与SSE重连。
稳定性验收至少每题3次，报告逐任务及端到端结果；动态市场数字只对照同次工具输出。

初始硬门禁：明确参数不可静默改写；成功证据不可丢失；每个要求有终态；安全违规为0；预算不超限。
模型质量沿用既有评测门槛并单列新组合集；未通过不得称为高可用，不以提高预算或放宽评测掩盖。
人工Judge校准仍独立执行，不能让生成模型自评通过代替发布评测。
