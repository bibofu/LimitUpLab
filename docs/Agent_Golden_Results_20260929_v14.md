## 已实现

- 执行器从实际生产模型请求的首条系统消息采集四个白名单字段：日期锚点、页面默认日期、页面默认股票和可查询本地日期。只保留成功返回请求的快照及系统消息哈希；不从答案或工具自述补造，不增加模型调用。
- 两阶段裁判均读取元数据；它只支持对应的运行范围，不能替代市场事实。逐轮报告保存快照及解析异常，输入拒绝等没有运行上下文的路径保留空列表。
- 保留原25条裁判诊断，增加12条日期、来源血缘、查询失败说明和过滤执行对照。其中3条专门检查证据不足，预期包含4个 `null` 判项。
- 明确最终交付不能由撤回草稿补足；合法来源ID不能抵消附带的无依据品牌归属；相同结果不能证明执行了额外过滤，两个工具不能自动证明上游独立。
- 校准预算上限由50升至100；每轮37题实际需要72次请求。合法未知与协议失败分开统计，异常不能算诊断匹配。

### 尚未完全通过的诊断

v8两轮均将 `source_lineage_unknown` 与 `additional_filters_unknown` 判为 `false`，预期为 `null`。它们的来源血缘或过滤执行信息缺失，裁判理由却把“没有支持”解释为“已经矛盾”。这属于确定错误与证据不足的分类缺陷，不能声称已完全校准。

已知共享上游、明确未执行过滤的负例，以及明确独立上游、已执行过滤的正例均按预期判定；合法/伪造可查询日期、泛化/明确故障说明也匹配。缺运行元数据的日期样例正确保留两个未知判项。

由于v8未知判定每轮仅命中2/4，本轮继续尝试v9的关系分类协议：模型直接选择证据关系，由代码映射判分，不按理由词语修正，不增加模型请求。全部327项Golden离线测试通过。

v9仍有分歧：上游血缘未知两轮均被判为矛盾，额外过滤未知第一轮判矛盾、第二轮才正确保留未知。两轮预期未知共8项，仅5项匹配。第一轮 `wrong_date` 的最终交付阶段另有一次 `ValidationError`，两个交付判项保留未知；独立可见审查仍正确识别错误日期。没有重试该题、隐藏异常或改写答案标准。

因此，步骤2的诊断扩展与运行已经交付，但“所有未知正确保留复核”的语义验收仍未达标。仅改变提示或输出标签尚不能保证模型做到这一点。本轮冻结v9收集**开发诊断基线**，不把校准分歧改写成通过，不按已知题目修正原始分数。它不满足裁判完全校准或自动发布验收。后续所有事实与来源fail须检查是否存在明确反证；代理复核另列，不能直接归因于Agent给出了已证实的错误，也不能混成新的自动通过率。
