# LimitUpLab V1.4 阶段里程碑

> 里程碑日期：2026-09-13
>
> 里程碑标签：`v1.4.0`（附注标签）
>
> 范围：`v1.3.2..v1.4.0`
> 定位：单一可恢复 ReAct 生产链路与旧 Agent 执行债务退役

## 版本结论

V1.4 的核心不是增加一个新页面，而是把聊天 Agent 从多套预编排流程收敛为一条可观察、可恢复的 LangChain + LangGraph ReAct 链路。模型在同一循环内读取问题、选择工具、观察结果并决定下一步；后端继续掌握金融数据、参数、证据、计算、权限和最终发布边界。

这一标签表示架构切换和文档基线完成，不表示模型答案质量、评分有效性或投资结果已经达到生产承诺。项目仍只用于研究与 Agent 工程展示，不构成投资建议。

## 已完成

### 单一 ReAct 执行链路

- 生产聊天入口统一到 `agents.chat -> react_runtime.runtime.GRAPH`。
- 使用 LangChain `AIMessage`、`ToolMessage` 和 `ChatOpenAI.bind_tools` 保留原生 tool-call ID 与多轮观察。
- LangGraph 自定义 StateGraph 固定为 Agent、Policy、Tools、Observe、Gate 五类节点；模型/工具/控制调用、截止时间和 recursion limit 均有上限。
- 独立查询可以有界并发；动态名单、条件分支和失败补证据通过下一轮观察驱动，不再依赖问法白名单或预先生成完整 DAG。
- `finish`、`update_task`、`read_evidence` 和 `compute_result` 使用严格 Pydantic 控制契约。

### 证据与确定性计算

- 每次运行拥有独立 EvidenceStore；完整工具结果不直接塞入模型上下文。
- 模型通过 evidence ID 阅读有界分页；筛选、排序、去重、交并差和聚合由确定性代码完成。
- 证据保留来源、参数、抓取时间、结果状态、缺失字段、来源截断与历史引用标记。
- partial/empty/error 不再统一压成成功；缺失或截断集合不能参与完整差集证明。
- 历史证据及其派生结果持续标记为 historical reference，不冒充本轮新鲜事实。

### Durable Run、SSE 与前端状态

- SQLite journal 保存 run、checkpoint、事件和逐 tool-call 结果。
- `owner_id + session_id + message_id` 提供请求隔离和幂等；相同 call ID 的不同参数被拒绝。
- 最终 Agent run、assistant message 和 response 在一个事务内发布。
- SSE 支持 accepted/progress/completed、事件游标只读重连和显式取消。
- 页面只在 validated completed 后发布答案，展示 complete/partial/empty/clarify/refuse/error/cancelled 等真实任务状态。
- 当前页面内重试复用 message ID；读取重连不会重新调用模型或工具。

### 旧链路退役

- 删除 legacy 聊天循环、Fast/Complex 路由、Task DAG、PlanPatch、独立 Completion/Replanner 和 Complex Graph。
- 删除旧 Planner Prompt、Capability 计划、Policy 自动补工具、参数重解释、通用确定性回答模板和对应执行器。
- 删除只验证旧协议的测试与模型夹具；保留仍有消费者的共享数据服务、历史 trace 读取和离线报告兼容。
- `LIMITUPLAB_AGENT_RUNTIME` 不再切换生产实现。需要回滚时部署已知 Git 提交，而不是在请求内静默跌回旧链路。

### 评测与真实验收

- Chat Eval V2 保留 89-case Dev、40-case 私有 Holdout 注入及七层历史报告格式；offline/shadow 不再冒充真实 ReAct Planner 成绩。
- Live runner 使用生产 ReAct 图与冻结工具世界，分别记录原始模型调用、实际业务工具、终态、轮数、token 和可选 Judge。
- 已用真实浏览器和真实数据抽查动态名单、双日期集合、排名后逐只 K 线、双股票比较及多轮改条件；结果和未解决 Bad Case 均记录在质量审查中。
- 标记前统一校验通过：完整后端回归 616 项及 6 个子测试通过，89 条公开 Dev 离线 gate 全部通过，前端 15 项通过，生产构建成功。后端依赖层仍有 3 条 LangGraph/websockets 弃用警告，前端保留 664.04 kB 单 chunk 提醒。

## 保持不变的业务边界

- LLM 不计算首板原始分数，不修改 Champion，不写交易结论。
- 评分、评级、候选过滤、集合统计和 Outcome 仍由确定性代码完成。
- 历史预测快照保持不可变；回测样本不能伪装为 live。
- 外部新闻和网页只作为带来源的解释证据，不直接进入评分。
- 买入、卖出、仓位、目标价、收益承诺和确定性预测继续被禁止。

## 已知未完成项

### P1

- Requests Provider 没有 ReAct `generate_messages` 协议，不能作为聊天回退；生产配置必须使用 LangChain。
- 模型直接返回普通文本时，当前 runtime 仍可能自动包装为 complete，绕过唯一 `finish` 出口。
- BC-033/034 表明最终门禁尚不能覆盖所有实体、日期、指标和计算口径错配。
- 评分 Policy 只版本化 factor weights，过滤、分箱、中性分和 confidence penalties 仍存在散落硬编码。

### P2

- 自定义图的核心预算、证据和持久化状态位于 Graph State 之外，未采用标准 LangGraph checkpointer/thread_id。
- 工具 JSON Schema、Registry 签名和 ReAct Catalog 仍是多份契约源。
- 旧 Query Understanding 完整解析器仍服务兼容评测并作为公共导出存在。
- 多进程 worker 接管、跨实例限流、强制中断底层网络请求和整页刷新自动发现活动 run 尚未实现。
- 正式私有 Holdout、三轮稳定性、Judge 校准和成本门槛尚未完成，不得以单题 Live 或单次浏览器抽查替代。
- 首板评分和盘前策略的样本外有效性仍不足，不能宣称稳定预测能力。

## 发布与回滚

`v1.4.0` 是不可移动的附注标签。标签只在本地创建；是否推送 `main` 和标签、是否触发生产部署由用户另行决定。生产部署前仍应执行 Windows/Linux 标签工作流、容器健康检查、数据库备份与真实业务接口验收。

回滚目标必须是已知历史提交或标签。V1.4 不保留进程内 legacy/task 开关，也不允许单个请求在 ReAct 失败后切回旧模板或旧执行器掩盖错误。
