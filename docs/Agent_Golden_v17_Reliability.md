# Golden v1.7 可靠性修复与重复基线

日期：2026-10-05。范围为评分可靠性和重复基线两项，未扩展产品业务工具覆盖。

## 口径和实现

- 版本为 agent-golden-v1.7、golden-judge-v14、golden-judge-calibration-v7；生产运行时为 react-runtime-v31。
- 执行器从Agent实际成功收到的评级证据视图采集预览省略条数、路径及source_truncated，关联原消息哈希。只接受已知filtered_out路径的结构标记，不复制任意数据源指令。来源完整与嵌套预览压缩可以同时成立。
- 裁判先识别独立性所修饰的对象，分别查询不推出上游独立；声称并行、无依赖等额外执行性质仍需证据。
- Finish.status为用户交付状态。完整有效证据支持的“无记录”或计数零可完成存在性/计数问题，标complete；请求名单无匹配行标empty；缺失或失败来源不能证明不存在。s18据此要求唯一complete，没有放宽为两种状态均可。确定性门禁拒绝研究complete仅引用error来源；partial仍可能包含足够的有效字段，不能一律拒绝，其自由正文否定断言仍需语义评审。本轮没有新增字段级交付依赖系统。
- 输入检查异常记录枚举阶段、errno/winerror和代码自有白名单位置，不保存异常正文、文件路径、请求数据或局部变量。预算持久化失败在进入provider前锁住预算，停止调用并归为harness_error，不重试模型。历史PermissionError根因仍未知。
- 诊断集保留原55题输入与标签指纹，新增6题，共61题、266判项、120次逻辑调用；含10个预期未知判项。主套件仍为61场景84回合。

## 离线验证

全部Golden测试、执行诊断、ReAct运行时、空结果交付、输入安全及模型适配器相关测试共580项通过，仅有第三方待弃用警告。生成日志不进入Git。

## 重复验证方案

在同一代码与配置下执行两轮完整裁判诊断，每轮预算120；既有12题smoke核心集重复3次，预算600。额外对s18、s19、m16各重复3次，预算150，补足核心集中没有覆盖的本次问题。合计预设调用预算990，不选择性覆盖失败结果。

全部失败、未知和运行异常进入复核清单；从自动通过场景中按固定哈希排序抽查10项，保留选择规则。代码和轨迹复核不等同于人工签核；人工待办保持未完成，不自动将judge_human_calibrated或human_signed_off改为true。

执行前冻结代码和题目，执行期间不改评分口径，不读取正在被写入的JSON报告；通过进程输出查看进度。原始报告、会话库和复核材料保存在新的output/golden/目录，并保留文件哈希。最终状态另记实际结果，未通过或待签核时不宣布发布验收完成。
