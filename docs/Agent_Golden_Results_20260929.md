## 本轮范围

套件升级为 `agent-golden-v1.3`，仍为 60 个场景、83 个用户回合。题目与预期事实未改；模型为 `deepseek-v4-flash`，裁判为 `golden-judge-v6`。12 个工具入口使用固定合成数据，运行数据库独立于生产。

## 评分器补强

- **最终交付单独判分**：裁判只读取最终正文来检查语义交付，撤回草稿不能替最终答案完成任务。
- **所有可见内容单独审查**：每轮都检查事实、来源和研究边界，包括已经展示后撤回的草稿。没有要求标注来源，也要检查回答主动声称的供应商。
- **错误必须能定位**：负向审查的失败须引用对应版本中真实存在的原文；定位无效降为未知并保存原判定，不能默认通过。
- **各维度独立**：名单或数值正确，但来源错误，分别计分；不能连带判成投资安全失败。
- **分阶段保留异常**：一阶段失败不抹掉另一阶段的结果；没有隐式模型重试，实际请求都计入预算。

报告新增 `visible_facts`、`source_attribution` 和按阶段的裁判异常统计。原 `facts` 继续表示确定性核对的结构化值。原文定位只能验证引用存在，不能保证裁判理解正确。

调用数指逻辑模型调用，包含 Agent、记忆和裁判；SDK 隐式重试关闭，请求前先预留预算。它不是题目数或纯回答请求数，也不等于账单确认的精确 HTTP 请求数；中断可能留下已预留但尚未发出的调用。

严格配对比较为 `matched_settings=true`，7 个原非 pass 结果转为 pass、0 个自动回退。两边题目、固定世界、评分器、模型及配置一致，生产代码允许变化。六个原失败对应来源和故障说明问题；另一项 m08 是 review 变 pass，但正文仍列出同样的可用日期，裁判这次漏看日期声明，不能把它算成 Agent 能力提升。

**60/60 是自动判分，不是全部正文已被人工确认正确。** 关键集为 35/36 自动通过，11/12 个场景三次全部通过；没有选择性补跑裁判或剔除未知结果。

一个 trial 包含一个场景的全部用户回合，执行 Agent 原有的答案校验与修复预算。通过表示整条链路的最终结果满足自动标准，不表示模型第一次提交 finish 就正确，也不单独衡量模型自身能力。

重复集唯一 review 是 m08 第一次的可用本地日期声明缺少裁判可见元数据。另两次也列出了相同日期，裁判却以“无证据否定”等理由判通过。因此，不能把它们当作元数据问题已解决；这同时显示裁判对证据不足的处理仍不稳定。三次均先澄清两个日期，再正确完成交集任务。

## v30 生产修复与边界

**故障说明**：只有没有本轮证据且存在真实业务执行失败时，兜底答案追加查询失败、未取得可核验结果、不能视为空或零只。策略拒绝、控制步骤、取消和恢复后的结果未知不算已确认业务失败。异常文本、工具名与摘要不回显；证据引用门禁保持生效。

取消在 stop 入口重新检查并优先处理。已有本轮证据时沿用原有部分结果，避免把重试前失败错误地说成重试后仍有缺口。没有新增状态或数据库字段。

**来源说明**：按本轮实际 `source/sources` 或逐条出处表述。工具品牌、接口名和缓存位置不是供应商证明；多个工具返回一致不自动证明上游来源相互独立。计算证据的内部 ID 只作血缘引用。

上述规则不含题目 ID、供应商替换或正则补丁，没有新增模型阶段。故障说明有确定性代码保障；来源规则仍依赖模型遵守，须继续用真实运行与复核检查。对应记录为 BC-097、BC-098。

## 已知评测缺口与下一步

1. **可信运行元数据尚未传给裁判**：m08 合法列出可查询本地日期，来源是 Agent 系统上下文；裁判只收到业务观测与证据，因而给出 review。不要把它算成 Agent 编造日期，也不要删掉合法回答来迁就评分。下版应传入可追溯元数据，并加入合法日期/伪造日期对照。
2. **来源独立性缺少专门诊断对照**：两个工具或两个来源 ID 不足以证明独立上游。下版需加入共享血缘与明确独立上游的正负样本。
3. **最终故障说明的裁判仍有宽松接受**：r04 基线的真实句子应加入诊断，并明确区分“回答未完成”和“数据查询失败”。不能因为草稿解释过而算最终交付。
4. **仍无人工金标签核或新盲测集**：当前预期由 Agent 编写，保留集已经公开并多次运行。正式发布需要由其他维护者保管新题，并对边界样本进行人工标注。
5. **额外过滤口径仍可能漏检**：关键集 m17 第三次第二轮声称“剔除ST与新股”，当前调用及返回资料没有证明执行了该过滤；5只计数正确不能证明额外口径成立。原始 pass 保留。后续应加入过滤已执行/未执行但恰好结果相同的对照，核对正文中的每个限定条件。“收盘未炸板”可按项目口径指收盘仍封住，不等于声称全天没有开板；不能仅凭盘中开板次数大于零就判成确定错误。

上述评分器改动需要新版本和新基线，不能在本次前后对照中途改变口径。
