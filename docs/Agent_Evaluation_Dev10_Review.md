### R1：OFF-B002 参考答案漏掉逐日收盘价

用户问的是“最近5根日K的收盘价及5日收益”，不是只问最新收盘价。
当前 `required_facts` 只列 `latest_close=11` 和 `return_5d_pct=null`，
`reference_answer` 也只给最新价及收益缺失，可能给遗漏逐日结果的答案错误示范。

下一步修改题目合同，不改窄用户问题：

- 参考答案覆盖全部五个日期与收盘价，以及缺失收益的原因。
- 明确“只给最新价”属于 task_completion 失败；日期/价格错误属于 grounding 失败。
- 允许额外解释四个间隔涨幅为10%，但必须明确不等于五日收益，不强制额外计算。
- 当前 World 只录制请求5根K线；若 Agent 合理查询6根以补收益基期而遇到 fixture error，
  先审夹具覆盖，不把它自动当作 Agent 错误，也不能编造第六根K线。

### R2：OFF-B026 未明确检查所问的价格

当前 `required_facts` 只有 `data_as_of=2026-09-10` 与 `data_fresh=false`。
World和参考答案已有 `latest_close=10.75`，但关键事实检查遗漏它。

下一步补齐对象、实际日期、价格及滞后披露。区分两类负例：

- 日期和滞后说明正确，但不报告价格：任务遗漏。
- 日期和滞后说明正确，但价格写为10.80：事实错误。

不因数据partial而允许关键数值错误；也不要求模型补造09-11价格。

### R3：OFF-B028 事实检查与允许输出字段未分清

当前 `required_facts` 列代码600001和分数70，却未列名称“样例甲”。
参考答案和用户要求是正确的，因此这不是已证实的运行失败；风险在于合同给Judge的信号不一致。

下一步明确：

- 交付事实是代码600001与名称“样例甲”。
- 分数70是背景证据，不是必须交付项；输出分数反而违反题目要求。
- 正例为代码名称；负例分别覆盖名称错误、漏名称、额外分数及额外解释。
- 行号、表格等不新增语义的排版不应判失败。

### R4：OFF-B030 不能以唯一工具名替代正确行为

World支持评级查询、名称筛选与质疑报告；筛选结果已含同一对象的分数和原置信度。
但 `required_facts` 只列 `first_board_ratings` 与 `first_board_critic`，
还包括用户未要求交付的 `snapshot_source`，而评级侧原置信度未作为检查项列出。

下一步在现有合同描述中写清：

- 允许“评级＋质疑”及“筛选＋质疑”路线，均须来自本轮、同对象同日期的有效证据。
- 三项必交付为分数70、原置信度60%、建议置信度40%，并正确区分单位和来源。
- 不要求回答snapshot_source；不能把内部字段披露当任务要求。
- 若实际走动态名称解析路线，再审第二步代码是否来自先前Observation；
  不能仅因调用两个工具就宣布覆盖了动态两步。
- 没有独立路线断言时明确由审阅核对，不为此新增通用判分DSL。

以上四项是合同修订建议，不是当前Judge已被证明误判的四个缺陷。
`answer.tool_contract` 在当前worker主要交给trace Judge，`required_facts`不是自动逐项执行的确定性断言。
不能只补JSON字段就声称建立了完整的机器判分保障。
